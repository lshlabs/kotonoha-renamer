# Kotonoha Renamer 검증 보고서

검증일: 2026-10-06. Windows 11 x64, Python 3.11.9, PyInstaller 6.22.3.

## localhost 포터블 전환

- 전용 WebView 창과 pywebview·WebView2 의존성을 제거하고 기본 브라우저 + 로컬 HTTP API로 전환했다.
- 서버는 `127.0.0.1`의 빈 포트에만 바인딩한다. 요청 Host·Origin·접속 키를 검사하며 외부 페이지 요청을 거부한다.
- 정적 자산은 HTML·CSS·JS 세 파일만 제공하고 파일 시스템 임의 경로는 제공하지 않는다.
- 실행 중인 서버에 EXE를 다시 실행하면 같은 화면을 연다. 화면의 종료 버튼은 작업 중단·기록 정리 후 서버를 종료한다.
- 새 빌드는 설치 프로그램 없이 포터블 ZIP으로 구성한다. Python과 폴더 선택용 Tk 런타임을 포함한다. Ollama·모델은 별도다.
- 설정은 EXE 옆 `data`에 저장하고 패키징 시 사용자 데이터는 제외한다. 기존 설치판과 일치하는 복구 저널은 경로·실행 ID·식별자·리비전을 검증한 뒤 복사하며 원본은 유지한다.

## 자동 검증

GUI 전용 44개 테스트를 통과했다. GUI·HTTP·파일 이동·복구·Ollama 준비 검증을 포함한다. 분리 전 공통 코드와 CLI를 함께 검증한 120개 테스트도 통과했으며, CLI 전용 테스트는 GUI 저장소에서 제외했다.

- HTTP를 통한 폴더 조회, 직접 수정, 최종 경로 확인, 적용, 원상복구와 파일 바이트 보존
- 인증 없는 요청·다른 Host/Origin·잘못된 JSON·과도한 요청·임의 파일 경로 거부
- 서버 종료 시 작업 취소·스레드 종료, 실행 중 서버 재접속, 포터블 데이터 위치
- 기존 설치판 저널 가져오기와 식별자가 다른 저널 거부
- 실제 Windows 원본 디렉터리 잠금을 유지한 채 하위 폴더 이동·복구
- 적용·복구 각 단계의 강제 프로세스 종료와 저널 재개
- 표현 바꾸기의 AI 없는 텍스트 치환·선택 범위·채택·되돌리기
- 기존 결과 폴더에 반복 적용, 이전 버전 결과 불러오기와 전체 복구
- 새 사용자 파일 보존, 오래된 적용 계획 거부, 과거 작업 기록과 현재 기록 구분

일반 브라우저와 실제 포터블 EXE를 통해 화면·폴더 조회·이름 적용·결과 폴더 재적용·전체 복구·파일 바이트 보존·종료를 확인했다. GUI에 개발용 버전 번호가 표시되지 않는지 확인하고, 배포 ZIP에 콘솔 실행 파일과 개인 데이터가 없는지 검증했다. 실행 파일의 Windows 버전 정보, 코드 버전, 파일명과 체크섬을 함께 검사했다.

## 검증 범위의 한계

실제 Ollama 설치·업데이트·대용량 모델 다운로드·삭제를 이번 전환 검증에서 반복하지 않는다. 기존 helper를 재사용한다. 번역 품질, GPU 환경별 성능, 백신·SmartScreen 동작은 이 테스트가 보장하지 않는다. 전체 음성·문서 번역은 범위에 포함되지 않는다.

GUI 배포는 `Kotonoha.exe` 하나와 `_internal` 런타임으로 구성한다. 콘솔 실행 파일·터미널 선택 메뉴·CLI 전용 테스트는 포함하지 않는다. 오래된 스크립트 복구는 CLI 저장소에서 처리한다.

## v1.0.1 응답 잘림 수정

- 제목을 최대 5개·원문 총 400자 단위로 분할하고 문맥은 대상 제목을 우선하여 제한한다.
- 끊긴 JSON이나 연결 오류에서도 완성된 항목만 보존하며 중복 ID는 제외한다.
- 정상 결과는 재요청하지 않고 미완료 제목만 기존 번역 강도로 한 번 재시도한다.
- 일부 미완료와 전체 실패를 GUI의 완료 상태와 구분하며 빈 후보를 만들지 않는다.
- 51개 제목의 분할·진행률·미완료 ID 재시도, 문자열 잘림, 연결 오류, 문맥 제한, GUI 실패 표시를 회귀 테스트로 검증했다.

실제 SuperGemma IQ4_XS와 기존 51개 제목 폴더에서 46개 결과를 보존하고 일본어가 남은 5개를 미완료로 표시하는 것을 확인했다. 번역 요청은 문맥 한도 안에서 잘림 없이 종료했다. 모델이 반환한 모든 제목의 번역 품질이나 형식 준수는 보장하지 않는다.
